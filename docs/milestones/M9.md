# M9 – 3D view and furniture

Status: **draft, awaiting approval**. Milestone branch: `m9-3d-view`.

From PLAN.md: walls extruded from the 2D plan using wall, room and floor heights; doors and windows cut out as openings; floors stacked; devices as instanced icons at their resolved positions (generic markers per device type until M5 adds the power icons); orbit/zoom on touch and mouse. Show one floor, a few floors, or all (exploded view). Clicking in 3D uses the same selection state as the 2D editor, so selecting a wall, room or device in one view selects it in the other; tapping a room or wall in 3D is also how M11 picks what a photo shows. Small `plugin-furnishing` (desk, table, shelf, rack shelving, cabinet, bed, sofa as simple boxes) to make rooms recognisable; it must need no core changes. Comes before M5 and M6, so circuit highlighting in 3D is part of M6.

**Done when:** an item selected in 2D is selected in 3D and the other way round, the large synthetic project stays usable in 3D on a laptop, and the furniture plugin was added without touching `packages/core`.

## Design decisions for this milestone (approve with the plan)

1. **3D is a view mode of the floor editor, not a separate page.** The editor gets a view switch: 2D, 3D and, on screens `md` and wider, 2D + 3D side by side. The mode is a search parameter (`?view=3d`), so it survives reload and deep links. Both views read the same `editorStore` selection, so selection sync needs no extra mechanism. On phones the switch replaces the canvas; the side panel (bottom sheet) stays and shows the selected item's panel in either view. All 3D code lives in `apps/web/src/features/view3d/` and is lazy-loaded, so three.js (~600 kB) is only downloaded when someone opens 3D.
2. **Selecting on another floor switches floor.** The editor edits one floor, and its selection is per floor. Tapping an item on another floor in 3D navigates to that floor and selects the item there (`openFloor(floorId, selection)`), and the 3D camera stays put. A tap on empty space clears the selection, as in 2D.
3. **Geometry is built by pure, unit-tested functions; three.js only renders it.** `view3d/geometry/` turns floor data into plain boxes and polygons with no three.js import:
   - **Walls** are boxes along the centreline (thickness × length × `wall.height ?? floor.height`). Openings are cut by splitting the wall into pieces along its length: full-height pieces between openings, a piece under each window (`sill`), and a lintel above each opening up to the wall height. No CSG library is needed. An end that meets another wall's end is extended by half its thickness, so L and T corners close without mitring.
   - **Rooms** become floor slabs from their polygons (triangulated with three's `ShapeUtils`, in the render step). Ceilings are not drawn, so rooms can be seen from above.
   - **Floors** stack at their `elevation`. Exploded view adds a gap of one floor height between visible floors; the offset is part of the same pure functions, so picking and markers agree with it.
   - **Devices** sit at `resolvePlacement` positions (core). A device with a floor placement and a `size` is a box of that size turned by `rotation` (furniture); every other device is a generic marker shaped and coloured by domain and type, facing out of its wall for wall placements. Unresolved devices are drawn at `approximate` in the issue colour, or skipped when there is none.
4. **Few draw calls, rebuilt per floor only.** All wall pieces of a floor are merged into one `BufferGeometry` with a triangle → wall id table, and the same for room slabs; devices are one `InstancedMesh` per marker shape with an instance → device id table. A floor's meshes are rebuilt only when that floor's data object changes (Immer keeps unchanged floors identical), so an edit on one floor never rebuilds the others. Selection is drawn as a separate highlight mesh of only the selected items, so selecting never rebuilds the merged geometry. The canvas uses `frameloop="demand"` and caps the device pixel ratio at 2.
5. **Picking uses react-three-fiber pointer events**, which give `faceIndex` (merged meshes) and `instanceId` (instanced meshes); the id tables map these back to `{ collection, id, floorId }`. A press that moves more than the tap threshold is an orbit, not a tap, matching the 2D editor's tap rules (same threshold constant). Walls hide openings' own selection in 3D for now: an opening is selected by tapping its 2D symbol; in 3D its cut-out is part of the wall.
6. **Camera: drei `OrbitControls`** (one finger rotates, two fingers pan and pinch-zoom, mouse wheel zooms, right-drag pans). Zoom to fit frames the visible floors. Opening 3D frames the current floor.
7. **Floor visibility:** a small floor menu in the 3D view: "Denna våning" (default), "Alla våningar", or a checklist of floors, plus an "Isärdragen" (exploded) toggle. Floors above the topmost visible one are hidden, so a lower floor is never covered.
8. **Devices in 2D get a generic layer now.** Devices are not drawn in the 2D editor yet, so "selected in 2D is selected in 3D" has nothing to select for devices. A generic `devices` editor extension draws every device as a small marker at its resolved position (culled, memoized, selectable, issue-coloured), and a device with a floor placement and a `size` as its rotated footprint. It is generic on purpose: M11 and M5 add icons and tools on top of it instead of a second device layer. Marker shape and colour per `(domain, type)` come from one registration (`features/devices/appearance.ts`), used by both 2D and 3D, with a generic fallback.
9. **`plugin-furnishing` needs no core changes.** `packages/plugin-furnishing` is a `DomainPlugin` (domain `furnishing`) with device types `desk`, `table`, `shelf`, `rack_shelving`, `cabinet`, `bed`, `sofa`; placement `floor` only; no ports; a default size per type in the plugin. Furniture is a normal `Device` whose `FloorPlacement` already has `at`, `rotation` and `size`, so the schema is unchanged. The web app gets its first plugin registry (`apps/web/src/plugins.ts`, `createRegistry([furnishingPlugin])`); M11 adds `plugin-power` there. The UI part, `apps/web/src/features/furnishing/`, adds a 2D tool (pick a type, tap to place; it takes the room under the tap as `roomId`), dragging to move, a rotation handle, and a panel (type, label, width, depth, height, rotation). Synthetic projects get no furniture (that would change core's generator); the e2e places it.
10. **Dependencies:** `three`, `@react-three/fiber`, `@react-three/drei` (runtime, `apps/web`), `@types/three` (dev). All three are in PLAN.md's stack table. Nothing else.
11. **Performance check.** A Playwright perf spec opens the large synthetic project in 3D with all floors visible, orbits for a few seconds and records frame times next to the existing `canvas-perf` spec. Target on a laptop: median frame under 33 ms (30 fps) with all floors, and under 16 ms with one floor. Selecting an item must not rebuild any merged geometry (asserted in a unit test with a build counter).

### T1 – 3D geometry builders

- **Depends on:** T0
- **Touches:** `apps/web/src/features/view3d/geometry/**` (+ tests)
- **Read:** ADR 0006 (wall, opening and side conventions), ADR 0008, `packages/core/src/geometry/placement.ts`
- **Goal:** the pure functions of decision 3: wall pieces with openings cut out and joined ends, room slab outlines, floor stacking and exploded offsets, device transforms (marker or sized box, facing for wall placements, approximate positions for flagged ones), bounds of the visible floors. Plain numbers and arrays only, no three.js import.
- **Acceptance:** tests for a wall with a door, a window (sill and lintel pieces) and two openings; an opening at a wall end; an opening wider than the wall (clamped, no negative pieces); a wall with its own height; L and T corners extended, free ends not; stacking and exploded offsets; a wall device facing each side; a ceiling device under a room's own ceiling height; a rotated sized floor device; an unresolved device. A test builds the large synthetic project's geometry within a time budget (in the perf test file).
- **Out of scope:** rendering.

### T2 – 2D devices layer

### T3 – 3D view
