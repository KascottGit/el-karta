# M3 – 2D editor: space

Status: **approved 2026-11-19**, in progress. Milestone branch: `m3-editor`.

From PLAN.md: Konva-based editor.

- Upload a floor plan image or PDF (pick the page; stored in Supabase Storage) as a floor's background.
- Scale: enter one known measurement by clicking two points.
- Draw and edit:
  - walls (polyline with snapping, thickness, optional height);
  - openings (door/window/passage on a wall; width, height, sill, hinge side, swing);
  - rooms (polygon, name, type, optional ceiling height);
  - zones.
- Optional grid lines.
- Add, switch and reorder floors and buildings.
- Pan/zoom with mouse and touch, viewport culling.
- Autosave per floor with debounce.

**Done when:** an estate-agent villa plan and a PDF office plan can be traced by hand in minutes, including doors and windows, and the editor stays smooth with the large synthetic project.

## Design decisions for this milestone (approve with the plan)

1. **Route:** `/projects/:projectId/floors/:floorId` is the editor; the project page links to it. A dev-only route `/dev/synthetic/:size` loads a synthetic project into the editor without the database, for performance checks and e2e.
2. **Editor state is separate from the model.** A small Zustand store holds tool, selection, viewport and in-progress drawing, so UI state never enters undo/redo or saving. All model changes still go through `applyEdit`.
3. **Walls stay independent segments** (as in the data model). Drawing a polyline creates one wall per segment. Dragging a corner moves every wall endpoint within 1 cm of it, so connected walls stay connected without a junction entity.
4. **Snapping and hit-testing are pure functions in `packages/core/src/geometry`**, unit-tested and reusable by later AI passes (wall-relative placement, M4).
   - Snapping covers endpoints, angle steps (0/45/90° relative to the plan), grid lines and projection onto walls.
   - Hit-testing finds the nearest wall and the offset along it.
5. **Creating and deleting floors and buildings is a repository operation, not a queued patch.** It runs immediately, because a new floor is a new row. `Repository` gains `createFloor` and `deleteFloor`; editing a floor's name or order stays a normal edit and is saved with that floor.
6. **Backgrounds:**
   - The uploaded file goes to `project-files/<projectId>/<attachmentId>.<ext>` with an `attachments` row.
   - A PDF page is rendered to an image in the browser with pdf.js; the rendered PNG is stored, so viewing never needs pdf.js.
   - `FloorData.background` and `scale` are used as the schema already defines them.
7. **Dependencies (in the stack table, added by the orchestrator in T0):** `konva` 10, `react-konva` 19, `pdfjs-dist` 6.

## Tasks

Common acceptance for every task:

- `pnpm typecheck && pnpm lint && pnpm test` pass.
- New logic has unit tests.
- UI text is Swedish via i18n keys.
- It works with touch on a phone-sized viewport.

### T0 – Setup (orchestrator)

- Add the three dependencies.
- Add the editor route with an empty page under `apps/web/src/features/floorplan/`, the `/dev/synthetic/:size` route, and the project page link.
- Commit on `m3-editor`, so every task worktree starts from it.

### T1 – Canvas foundation

- **Depends on:** T0
- **Touches:** `apps/web/src/features/floorplan/canvas/**`, `apps/web/src/features/floorplan/editor-store.ts`, editor page layout
- **Goal:** the Konva stage the other tasks draw on.
  - Layers in a fixed order: background, grid, rooms/zones, walls, openings, overlays.
  - A world (metres, y down) ↔ screen transform.
  - Pan and zoom with wheel, drag, pinch and two-finger pan; zoom to fit.
  - The editor store holds tool, selection and viewport.
  - Viewport culling helper: query the items whose bounding box intersects the view.
  - A toolbar and side-panel slot that tasks register into, rather than editing a shared file.
  - A read-only renderer of the existing walls and rooms, so T2–T7 have something to build on.
  - Keyboard: Escape cancels, Delete removes the selection, Ctrl+Z / Ctrl+Shift+Z undo and redo.
- **Acceptance:**
  - Transform and culling are unit-tested.
  - `/dev/synthetic/large` renders the busiest floor.
  - A pan frame takes under 16 ms on a laptop, measured and reported.
- **Out of scope:** editing tools.

### T2 – Floors and buildings

- **Depends on:** T0 (parallel with T1)
- **Touches:**
  - `packages/core/src/repository/**`, `packages/data-supabase/**`
  - `apps/web/src/model/store.ts` (adding/removing floor documents)
  - `apps/web/src/features/projects/**`, a floor switcher component
- **Goal:**
  - Add, rename, reorder and delete floors and buildings.
  - New floors default their elevation to the floor below's elevation plus height, and their height to the project kind's default.
  - Switching floors in the editor changes the URL.
  - `createFloor` / `deleteFloor` in `Repository`, `InMemoryRepository` and `SupabaseRepository`.
- **Acceptance:**
  - Repository unit and integration tests (including RLS: a viewer cannot create a floor).
  - Store tests for adding and removing a floor while other floors have pending changes.
  - Deleting a floor asks for confirmation and also removes cross-floor connections to it.
- **Out of scope:** drawing anything.
- **Deviation (accepted):** buildings can be added, renamed and removed, but not reordered. `Building` has no order field, and adding one would be a schema change; they are listed by name until a later milestone needs an order.

### T3 – Background and scale

- **Depends on:** T1
- **Touches:**
  - `apps/web/src/features/floorplan/background/**`
  - `packages/data-supabase/**` (attachment upload, signed URL)
  - core edits for `background` / `scale` if needed
- **Goal:**
  - Upload an image or PDF.
  - For a PDF, pick a page; it is rendered to PNG at a resolution suitable for tracing.
  - Store the file and the attachment row, set `background`, and show it on the background layer at the right scale.
  - Adjust opacity (UI-only) and offset/rotation.
  - Scale tool: click two points and enter the real length in metres, which sets `scale` with `source: 'user'`.
- **Acceptance:**
  - Unit tests for the scale computation and image-to-world placement.
  - Integration test for upload and RLS on the storage path.
  - A plan can be scaled to within 1% from one known dimension.
- **Out of scope:** reading dimension text automatically (M4).

### T4 – Walls

- **Depends on:** T1
- **Touches:**
  - `packages/core/src/geometry/snap.ts` (+ tests)
  - `apps/web/src/features/floorplan/walls/**`
- **Goal:**
  - Wall tool: click or tap to place a polyline with snapping. Double-click, tap the last point, or press Escape to finish.
  - Select a wall and edit its thickness and height in the side panel.
  - Drag endpoints, moving connected corners together.
  - Delete a wall.
  - Show devices and openings beyond a shortened wall as flagged (validation already reports them).
- **Acceptance:**
  - Snapping is unit-tested: endpoint, angle, grid, priority between them.
  - Undo and redo work for every action.
  - Drawing 20 walls is fluid on the large synthetic project.
- **Out of scope:** openings.

### T5 – Openings

- **Depends on:** T4
- **Touches:**
  - `packages/core/src/geometry/` (projection onto a wall, if T4 did not provide it)
  - `apps/web/src/features/floorplan/openings/**`
- **Goal:**
  - Door, window and passage tools: click or tap on a wall to place one at the projected offset, with default sizes (door 0.9 × 2.1, window 1.2 × 1.2 with sill 0.9).
  - Drag it along the wall.
  - Edit width, height, sill, hinge and swing.
  - Draw the door swing arc.
  - Openings can't be dragged beyond the wall end; existing invalid ones show the validator's warning.
- **Acceptance:**
  - Unit tests for placement and clamping.
  - Undo and redo.
  - Validator issues show on the opening.
- **Out of scope:** detecting openings from images (M4).

### T6 – Rooms and zones

- **Depends on:** T1 (parallel with T4)
- **Touches:** `apps/web/src/features/floorplan/areas/**`, polygon helpers in `packages/core/src/geometry/polygon.ts`
- **Goal:**
  - Room tool: draw a polygon with snapping to wall corners and existing polygon points.
  - "Fill room": click inside closed walls to create the room polygon from them.
  - Edit name, type (Swedish labels for `RoomType`) and ceiling height.
  - Drag vertices.
  - Zone tool: the same polygon drawing, with name only, drawn translucent over rooms.
  - Labels at the centroid.
- **Acceptance:**
  - Unit tests for fill-room (rectangular and L-shaped rooms, open walls give no room) and vertex editing.
  - Validator problems (self-intersection) are shown.
- **Out of scope:** devices.

### T7 – Grid lines

- **Depends on:** T1 (parallel)
- **Touches:**
  - `apps/web/src/features/floorplan/grid/**`
  - `packages/core/src/geometry/grid.ts` (+ tests)
- **Goal:**
  - Optional grid per floor: add lines at positions, labelled A–Z along x and 1–n along y, with auto-labelling and editing.
  - Render them on the grid layer.
  - Core helper `gridCell(grid, point)` that returns e.g. `"C4"`, for search in M6.
- **Acceptance:** unit tests for labelling and `gridCell`, including points outside the grid.

### T8 – Autosave and conflicts

- **Depends on:** T0 (parallel with T1, T2)
- **Touches:**
  - `apps/web/src/features/floorplan/save/**`, a save-status component
  - `apps/web/src/model/` hooks only, not `store.ts` internals
- **Goal:**
  - Save with a debounce (about 1.5 s after the last edit, at most every 10 s while editing).
  - Save before leaving the page or switching floors.
  - A status indicator: saved / saving / not saved, with a retry.
  - If a save keeps failing, keep the changes and retry with backoff.
  - Show rejected changes (`conflicts`) in a list the user can dismiss, and explain them.
- **Acceptance:**
  - Unit tests with fake timers and `InMemoryRepository`: debounce, retry, saving on unload.
  - Conflicts are surfaced.
- **Out of scope:** Dexie/offline persistence (M8).

### T9 – Performance pass

- **Depends on:** T3–T7
- **Touches:** rendering code in `features/floorplan/**` only
- **Goal:**
  - Profile `/dev/synthetic/large`: culling, Konva layer caching, avoiding React re-renders on pan, and batching hit-tests.
  - Add a repeatable measurement: a Playwright script that pans and zooms and reports frame times.
- **Acceptance:**
  - On a laptop, p95 frame time under 16 ms while panning the large project.
  - On a phone-sized viewport with CPU throttling ×4, "usable", recorded as p95.
  - Numbers reported.

### T10 – End-to-end tracing test

- **Depends on:** all
- **Touches:** `apps/web/e2e/**`, a small test fixture plan image
- **Goal:** a Playwright test that:
  - signs in and creates a project;
  - uploads a plan image and sets the scale;
  - draws four walls, a door and a window;
  - fills a room and names it;
  - adds a second floor;
  - reloads, and checks that everything was saved.

## Order and parallelism

| Wave | Tasks (parallel within a wave) |
| ---- | ------------------------------ |
| 0    | T0 (orchestrator)              |
| 1    | T1, T2, T8                     |
| 2    | T3, T4, T6, T7                 |
| 3    | T5                             |
| 4    | T9, T10                        |

Each task: implementer → reviewer → fixes if needed → orchestrator merges into `m3-editor` and runs the full suite. After wave 4, the orchestrator does a final check:

- every suite, including Supabase and e2e;
- tracing a real villa plan and a PDF office plan by hand in the dev build, with screenshots.

Then it opens the M3 PR and stops for review.
